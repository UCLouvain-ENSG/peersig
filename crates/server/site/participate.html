Participate

Join in three steps

About three minutes. Nothing leaves your computer before you have seen it, and you can leave at any time from the app.

{{NOTICE}}

  1. Download PeerSig

    macOS

    Apple Silicon Intel
    macOS 12 or newer · Apple Silicon is M1 and newer
    The first time: open the disk image and drag PeerSig to Applications, then open it. macOS says it cannot check the developer: open System Settings → Privacy & Security and choose Open Anyway. PeerSig then installs its capture service, and asks for your password once.

    Windows

    Download for Windows
    Windows 10 and 11 · x64 · .msi installer
    The first time: Windows says it does not know the publisher (the builds are not signed yet): choose More info, then Run anyway. PeerSig then installs its capture service, and Windows asks for an administrator's permission once. Nothing else to install.

    Linux

    .deb .rpm AppImage
    x86_64, with a desktop · .deb for Debian and Ubuntu, .rpm for Fedora, RHEL and openSUSE
    Install with sudo apt install ./PeerSig_*_amd64.deb or sudo dnf install ./PeerSig-*.x86_64.rpm (zypper on openSUSE): the package gives the capture probe the rights it needs. The AppImage runs the app, but cannot give the probe those rights. A server without a desktop: see Linux server.

    Linux server

    For a dedicated observer: a machine the study runs, without a desktop, whose traffic may be published. It needs an observer code (OBS-…) from the study team, reports every day, and its items are published without threshold. To take part from your own computer, use the Linux tab.

    .deb .rpm
    x86_64 · systemd · the probe and peersig-observer, no desktop needed 
    sudo apt install ./peersig-observer_*_amd64.deb    # Debian, Ubuntu
sudo dnf install ./peersig-observer-*.x86_64.rpm    # Fedora, RHEL
sudo peersig-observer configure                    # asks for the code, starts it
sudo peersig-observer status
    Steps 2 and 3 below are for the app: an observer's code comes from the study team, and configure takes it. Each day's items appear at /v1/released/observers. How observers work.

  2. Get your code

    Why a code? The collection only accepts ballots from enrolled participants, so that nobody can reach it uncontrolled from the internet and flood it with made-up results (spam). A code lets one computer send at most {{TOKENS}} anonymous ballots a week. It does not identify your ballots: they carry tokens signed blind, which cannot be traced back to the code.
    {{METHODS}}

  3. Open PeerSig and paste it

    The addresses are filled in already: the server {{SERVER}}{{RELAY}}. Paste your code, choose whether to share the server names your non-browser applications connect to, and join.

    Then, every Monday, PeerSig shows you last week's list and waits a day: untick anything you do not want to send. It then sends each item as a separate anonymous ballot. The icon in the menu bar (on Windows, the notification area) tells you when.
