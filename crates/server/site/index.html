Anonymity

We learn about software, not about you

What could describe a person is who runs which software. Each layer below keeps that from the study, the relay, and anyone who gets the database.

You review it first

Each week's list waits a day in the app. Untick anything, it is never sent. Nothing leaves while the app is closed.

Blind tokens

The server signs your tokens through a veil, as in anonymous e-voting. It knows a ballot comes from a participant, never which one.

One ballot per item

Every item travels alone, with its own token, at a random time. The server cannot tell which items come from the same person.

A relay hides your address

Ballots are sealed for the server and handed to a relay (Oblivious HTTP). The relay sees who, not what; the server sees what, not who.

Counts, not ballots

The server keeps one counter per item and week. No ballot, no arrival time, no address: the database cannot say who sent what.

Published only when common

An item appears in the public table only once {{K_HELLO}} participants reported it in the same week ({{K_DOMAIN}} for server names). Rare software stays private.

The full design, with its limits, is in docs/privacy.md.

JA4

A fingerprint of the handshake, not of a person

Every encrypted connection starts with a ClientHello: the client lists what it supports, in clear. JA4 condenses it into three parts. The same TLS library, set up the same way, always gives the same JA4.

Why the server name matters

Applications that share a TLS library share a JA4. With the server name (SNI) that participants may choose to share, for non-browser applications only, the table tells them apart. Examples from a test run:
